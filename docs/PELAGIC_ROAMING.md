# 黄尾乌尾鮗鱼群跨已加载海域巡游

2026-10-04，用户确认先让现有一类开放水层鱼贯穿连续海域，完成后再推广到其他鱼群。本轮保留黄尾乌尾鮗的原个体与小组，不新增动物、地形或形态细节。实现源仅涉及 `oceanEcology.js`、`OceanApp.jsx` 和 `oceanPelagicSpecies.js`；原渲染器和世界跟随继续按稳定个体 ID 工作。

## 运行与保存规则

| 规则 | 当前实现 |
| --- | --- |
| 活动范围 | 只在最多九个已加载分区中运行，每格最多二十条动物记录，死亡记录占容量。未加载区域保存后冻结。 |
| 身份与时钟 | `fusilierRoamingVersion=1` 只追加移动元数据，保留原 ID、群组、位置、死亡、体能和摄食历史。个体携带 `mobileTimeSec`，巡游、状态变化、摄食期限和动画均使用该时钟。 |
| 群游连续性 | 每个固定步开始时读取整个活动窗口内同组鱼的姿态快照，按 ID 排序计算中心；越过格界的同伴仍参与间距和靠拢。较大间距时降低路线权重，不能拖动、克隆或复活落后的同伴。 |
| 运动与净空 | 所有实际步进使用完整 XYZ 位移加有限残余水流预算。沿步的四个参考点检查实际海床／岩体／珊瑚支撑、水柱和水面净空；被挡时使用有限局部候选。历史重叠位置只在普通速度预算内向上恢复。 |
| 越界归属 | 所有分区完成同一固定步后才转移个体，避免目的分区再更新一次。提交时重新检查存活、原所有者成员关系、活动／锁状态和死亡在内的容量。 |
| 食物与历史 | 越界步仍扣原所有者的浮游资源，下一步扣新所有者。地方资源、账本、计数和分区钟留在原地；体能、个体钟、摄食期限和成功摄食时间随鱼保留。 |
| 防止重复补群 | 出生／迁出与迁入格保留 `pelagicEverOccupied`。已有活体、死亡、已检查类别或历史占用均阻止把离开的鱼群重新分配出来。 |
| 存储失败 | 移动元数据在激活前保存；失败只显示原记录。所有权通过共同 `saveMany` 事务保存，卸载前冻结退出格，失败保留原窗口以便重试。读取失败不能被解释成未访问分区而重新生成动物。 |
| 旧适配器 | 没有原子批量保存接口的存储维持原有局部巡游；即使读到已有漫游元数据，也不发布非原子跨格转移。 |

原小范围路线的相位在升级时保持，较大路线中心经过平移，使升级瞬间的参考目标连续；保存的实际位置不会跳到新轨道。路线长度、周期、群体权重、速度、深度和低光规则均是定性展示参数，不是野外校准值。这里实现的是已加载海域内的连续巡游，不是季节迁徙、繁殖、全海演化、全局寻路或完整身体碰撞，也不保证所有地形／容量组合下都能通过。
